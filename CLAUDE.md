# CLAUDE.md

Guidance for Claude Code (and humans) working in this repository.

## What this project is

A benchmark of **soft-CORN** against 11 core alternatives (and 20 more in the extension studies) for learning from
**set-valued ordinal labels**.
soft-CORN is CORN trained on the expected subset membership under a soft label. The alternatives
include soft-CORAL / soft-OR (Matton et al., 2026), ordinal label-distribution learning (OLDL; Wen et
al., ICCV 2023), partial-label likelihood, soft and hard cross-entropy, and hard CORN / CORAL.

It was built to decide whether an MSc thesis's soft-CORN loss can stand alone as an ML paper.
**Read `REPORT.md` first**: it holds the verdict, every result, and the methodological decisions with
their reasons. `FUTURE_WORK.md` lists the next experiments in priority order.

## Data location (`SCB_DATA`)

Raw data, features, run logs (`*.npz`) and the Hugging Face cache **never live in the repo**.
`ordbench/paths.py` resolves the data root in this order:

1. the `SCB_DATA` environment variable;
2. `D:/soft-corn-benchmark-data`, if it exists on Windows (the original machine);
3. `<repo>/data` (git-ignored).

On a new machine, set `SCB_DATA` to a disk with a few GB free. To reuse existing work, copy
`processed/` (features + labels, ~0.3 GB) and optionally `results/` (run logs, ~0.4 GB) from the old
data root. Copying `processed/` matters if results will be merged across machines:
re-running `02_build.py` on other hardware or library versions can change the embeddings slightly.

## Commands

```bash
python -m pytest -q                     # 114 tests, ~60 s (one needs CUDA and skips without it)
python -m ruff check .                  # lint (the same check runs in CI)
python scripts/01_download.py           # raw data -> $SCB_DATA/raw
python scripts/02_build.py              # features + set labels -> $SCB_DATA/processed (needs a GPU, ~30 min)
python scripts/03_run.py --bodies linear                  # frozen-feature benchmark (resumable)
python scripts/03_run.py --bodies mlp --n_train 512 full
python scripts/03_run.py --m 2 --bodies linear --n_train 512 2048 full --out $SCB_DATA/results/m_ablation
python scripts/04_synthetic.py --bodies linear            # synthetic benchmark (resumable)
python scripts/06_finetune.py --datasets cb               # fine-tuning (resumable; one dataset per call keeps runs short)
python scripts/07_checks.py             # grid-edge checks, hyperparameter sensitivity -> results/checks.md
python scripts/05_analyze.py            # selection, tests, tables, figures -> results/, figures/ (core benchmark + fine-tuning)
python scripts/09_setpred.py            # needs scripts/08_replay.py first; conformal sets, reliability, temperature scaling
python scripts/10_extensions.py         # analysis of the extension studies -> results/extensions.md
SCB_DATA=... bash scripts/run_frozen.sh .venv/Scripts/python.exe     # all frozen-feature stages in order
SCB_DATA=... bash scripts/run_finetune.sh .venv/Scripts/python.exe main seeds lpft refs   # chosen fine-tuning stages
SCB_DATA=... bash scripts/run_extras.sh .venv/Scripts/python.exe                          # replay, targets, baselines, variants, shift, personal
python scripts/01_download.py provoice && python scripts/02_build.py provoice provoice_task   # natively set-valued study (0.55 GB download)
SCB_DATA=... bash scripts/run_provoice.sh .venv/Scripts/python.exe                        # its runs (driver-level splits, retries) and scripts/14_provoice.py
SCB_DATA=... bash scripts/run_provoice.sh .venv/Scripts/python.exe kcurve kanalyze         # K-curve personalisation (~3 h, 1,008 cells), then scripts/run_kcontrol.sh
```

Every runner **skips finished cells** (one `.npz` per cell), so it can be interrupted and restarted
safely. Runners loop over seeds outermost, so a partial run still covers every dataset.
`03_run.py` takes `--lrs` / `--wds` to override the grid, and `--out` to write to a separate folder.
Keep ablations and checks out of `results/real`, because `05_analyze.py` treats that folder as the
main m = 3 benchmark. Every extension writes to its own folder (`targets_*`, `baselines_*`, `synth_*`,
`real_extra`, `shift`, `personal`, `finetune_<variant>`); `05_analyze.py` and `10_extensions.py` read them.
New methods never go into the default `METHODS` list, which is the core twelve.

## Protocol decisions (do not change silently; each has a reason in REPORT.md)

- **Selection is offline and matched.** Validation and test metrics are logged for every
  (checkpoint, config). Each test metric is read at the checkpoint chosen by its validation
  counterpart: set-MAE → set-MAE, NLL → NLL / held-out NLL, RPS → RPS. Never select on test data.
  Held-out raters are used only for evaluation.
- **Linear probes use Adam with a coupled L2 penalty, not AdamW.** Decoupled decay does not
  regularise 768–1,536-d linear heads; every method overfitted CommitmentBank.
- **Grid:** lr {3e-4 … 3e-2} × L2 {1e-3 … 10}; 2,000 steps; evaluated every 100 steps. Edge checks
  (`wd_check`, `mlp_lr_check`) showed it is not binding.
- **All methods share** data order, initialisation, splits (`03_run.split`, fixed seeds) and
  annotator sampling (`02_build.ANNOTATOR_SEED`).
- **Fine-tuning:** the head gets lr 1e-3 and its biases are initialised at the training-label
  marginal (`finetune.init_bias_to_prior`). Without this, CORAL's thresholds stay stuck. The backbone
  lr is chosen on seed 0 and reused for later seeds.
  The result depends on this choice: fitting the head first on frozen features (LP-FT,
  `--init lpft`) lifts soft-CORAL and removes most of soft-CORN's lead. Quote fine-tuning comparisons
  with every method's best variant (`scripts/07_checks.py`, "best variant per method"), not the
  main protocol alone.
- **Extension studies keep the core protocol** (same splits, grid, selection, seeds). A method run in
  its own folder is comparable to the core run of the same cell because every method seeds its own head
  initialisation. The exact set likelihood needs the number of raters per set (`m`), so runs now log
  `xnll`, a target-agnostic validation criterion; selection by `nll` compares losses on the uniform-over-set
  label and favours that target. The refactored runners reproduce stored cells bit for bit.
- **Natively set-valued data (ProVoice) has no raters behind its sets.** Splits keep a driver's answers together
  (`03_run.py --test_frac 0.25 --val_frac 0.17`: 3 test and 2 validation drivers of 12, 20 draws; the defaults 0.2 / 0.1 are
  unchanged for every other dataset). Metrics are read against the accepted sets (NLL against the uniform-over-set label,
  `pll`, set-MAE, RPS); held-out-rater metrics and the rating-based targets do not exist. A hard-label loss trains on the
  lower median of the set. Only 6.8% of the answers are sets, so most of the comparison is about singleton answers.
- **The K-curve personalises by a driver code** (one-hot, L2 shrinkage towards the population model); the held-out driver and
  two validation drivers have only K answers in training, so selection on the validation drivers rehearses the test driver's
  situation. The other prompt of a calibration answer's window is never tested. It is one adaptation arm, not the thesis's
  L2-SP / ANIL. Hard-label losses use the lower median of a set, a tie-break that costs about 0.07 NLL against a random member.
- **Replay needs linear heads** (members train independently, so a replay reproduces the logged metrics
  exactly; the stored files record the deviation). Conformal sets calibrate on the validation items that also
  selected the checkpoint, which makes coverage slightly optimistic.
- **Statistics:** Nadeau–Bengio corrected t-test per problem (plain paired t-test for synthetic,
  where seeds are independent draws); Friedman/Nemenyi via `autorank`; Bayesian signed-rank via
  `baycomp`, which assumes higher is better, so its probabilities are flipped for our lower-is-better
  metrics (`ordbench.analysis.pairwise_table`; its sign is first argument minus baseline). Across problems
  `random_effects` gives a DerSimonian–Laird summary, a stand-in for the Stan hierarchical test.

## Conventions

- **Reuse open-source libraries** rather than re-implementing: `coral-pytorch` (CORAL/CORN),
  `autorank`, `baycomp`, `transformers`, `sentence-transformers`, `open_clip`. Hand-written code that
  duplicates a library must be checked against it in a test (see `test_losses.py`, `test_heads.py`).
- Match the surrounding code: module docstrings explain *why*, sparse inline comments, no new
  frameworks.
- New loss: add it to `losses.py` (`HEAD_OF`, `compute_loss`, and `OUTPUT_OF` for a new head type), add a test, and add a
  label in `05_analyze.py` / `10_extensions.py` (`LABEL`). New heads must run inside the CUDA graph: no CPU
  tensors created in the step.
- New dataset: add a builder to `02_build.py` and an input loader to `finetune.load_inputs` (VADER and
  ConvAbuse share `ordbench/extra_data.py` for that). It must produce `X`, `K`, `item_id`, and per-m
  `mask_m{m}` / `ho_m{m}` / `valid_m{m}`; optional `group` keeps rows of a group in one split. Natively
  set-valued tables: `python -m ordbench.native`, then `03_run.py --m 0`.
- Report results honestly, including where soft-CORN loses; every claim in REPORT.md must trace
  to a table in `results/`.

## Environment gotchas

- PyTorch must be the CUDA build for GPU runs; install it first, then `pip install -r requirements.txt`.
- `run_cell` captures each training step in a CUDA graph, which cuts kernel-launch overhead when the
  CPU is busy. It falls back to eager mode on CPU. `test_cuda_graph_training_matches_eager` guards
  equivalence.
- A 6 GB GPU fits one fine-tuning process (CommitmentBank, 256 tokens, uses about 5.9 GB). Run
  fine-tuning jobs one at a time; frozen-feature runs can run two or three in parallel.
- When running under Claude Code, background shell jobs may be killed after 2 hours. Split long runs by
  `--seeds` or `--datasets`; they resume where they stopped.
- Run GPU stages one at a time: two jobs time-slice the card and finish no sooner. Never edit a shell script
  while bash is executing it; stop it, edit, restart (all stages resume).
- Heredocs in some agent shells collapse double backslashes; write patch scripts with a file-writing tool
  instead of `python - <<EOF` when strings contain `\n`.
- `transformers` 5 needs `tiktoken` and `sentencepiece` for the DeBERTa-v3 tokenizer (in requirements.txt).
- `transformers` 5 loads a checkpoint in its **stored dtype**, and DeBERTa-v3-base is stored in fp16: AdamW's `eps = 1e-8`
  then underflows and the first optimiser step turns every weight into NaN (the first DeBERTa fine-tuning run trained nothing
  and sat at the label-marginal baseline; those runs are quarantined in `results/_invalid_deberta_fp16_weights*`).
  `finetune.TextEncoder` / `ImageEncoder` now pass `dtype=torch.float32`; `test_text_encoder_trains_in_fp32_even_if_the_checkpoint_is_fp16`
  guards it. A fine-tuning result at the feature-free NLL for every method means the run did not train; check that first.
- Two `run_cell` launches that shared the GPU with another heavy process aborted with `device-side assert triggered`
  (index out of bounds in the first training step); the same cells ran on an idle or memory-starved card, and every cell
  stored before an abort is bit-identical to a clean re-run, so an abort loses a cell but never corrupts one.
  `scripts/run_provoice.sh` retries a stage; do the same for other long runs on a shared GPU.
- On Windows, set `PYTHONIOENCODING=utf-8` when redirecting script output; the summary tables
  contain non-ASCII symbols.
