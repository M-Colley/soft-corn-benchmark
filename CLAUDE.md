# CLAUDE.md

Guidance for Claude Code (and humans) working in this repository.

## What this project is

A benchmark of **soft-CORN** against 11 alternatives for learning from **set-valued ordinal labels**.
soft-CORN is CORN trained on the expected subset membership under a soft label. The alternatives
include soft-CORAL / soft-OR (Matton et al., 2026), ordinal label-distribution learning (OLDL; Wen et
al., ICCV 2023), partial-label likelihood, soft and hard cross-entropy, and hard CORN / CORAL.

It was built to decide whether an MSc thesis's soft-CORN loss can stand alone as an ML paper.
**Read `REPORT.md` first**: it holds the verdict, every result, and the methodological decisions with
their reasons. `FUTURE_WORK.md` lists the next experiments in priority order.

## Layout

| path | content |
|---|---|
| `ordbench/losses.py` | all 12 losses, PMF decoding per parameterisation (`HEAD_OF`), registry (`compute_loss`) |
| `ordbench/heads.py` | `EnsembleHead` (all hyperparameter configs as one vectorised model) and `MemberAdam` (torch Adam/AdamW, one param group per config) |
| `ordbench/train.py` | `run_cell`: trains every method on one training set, logs val/test metrics over training; CUDA-graph capture; `LRS`/`WDS` grid |
| `ordbench/metrics.py` | `prepare` (prediction-independent parts) and `evaluate` (sync-free metrics, held-out raters, set types, calibration, prediction intervals) |
| `ordbench/analysis.py` | offline selection (`select`, `collect`), corrected resampled t-test |
| `ordbench/synthetic.py` | five rater-distribution families and the exact population target E[u_S \| x] |
| `ordbench/finetune.py` | end-to-end fine-tuning (mpnet for text, OpenCLIP ViT-B/16 for SCUT; prior-bias or LP-FT head init; other text backbones) |
| `ordbench/paths.py` | data root (`SCB_DATA`), see below |
| `scripts/01_download.py` … `07_checks.py` | pipeline: download, build features and set labels, frozen-feature runs, synthetic runs, analysis, fine-tuning, grid-edge checks and sensitivity |
| `scripts/run_frozen.sh`, `run_finetune.sh` | every run stage in order, one job at a time (resumable) |
| `results/` | small tables and `summary.md`, regenerated by `05_analyze.py` (committed) |
| `figures/` | figures, regenerated by `05_analyze.py` (committed) |
| `tests/` | correctness tests; CI runs them on CPU |

## Data location (`SCB_DATA`)

Raw data, features, run logs (`*.npz`) and the Hugging Face cache **never live in the repo**.
`ordbench/paths.py` resolves the data root in this order:

1. the `SCB_DATA` environment variable;
2. `D:/soft-corn-benchmark-data`, if it exists on Windows (the original machine);
3. `<repo>/data` (git-ignored).

On a new machine, set `SCB_DATA` to a disk with a few GB free. To reuse existing work, copy
`processed/` (features + labels, ~0.3 GB) and optionally `results/` (run logs, ~0.4 GB) from the old
data root. Copying `processed/` matters if results will be merged across machines:
re-running `02_build.py` on other hardware or library versions can change the embeddings slightly.

## Commands

```bash
python -m pytest -q                     # 35+ tests, ~45 s (one needs CUDA and skips without it)
python -m ruff check .                  # lint (the same check runs in CI)
python scripts/01_download.py           # raw data -> $SCB_DATA/raw
python scripts/02_build.py              # features + set labels -> $SCB_DATA/processed (needs a GPU, ~30 min)
python scripts/03_run.py --bodies linear                  # frozen-feature benchmark (resumable)
python scripts/03_run.py --bodies mlp --n_train 512 full
python scripts/03_run.py --m 2 --bodies linear --n_train 512 2048 full --out $SCB_DATA/results/m_ablation
python scripts/04_synthetic.py --bodies linear            # synthetic benchmark (resumable)
python scripts/06_finetune.py --datasets cb               # fine-tuning (resumable; one dataset per call keeps runs short)
python scripts/07_checks.py             # grid-edge checks, hyperparameter sensitivity -> results/checks.md
python scripts/05_analyze.py            # selection, tests, tables, figures -> results/, figures/
SCB_DATA=... bash scripts/run_frozen.sh .venv/Scripts/python.exe     # all frozen-feature stages in order
SCB_DATA=... bash scripts/run_finetune.sh .venv/Scripts/python.exe main seeds lpft refs   # chosen fine-tuning stages
```

Every runner **skips finished cells** (one `.npz` per cell), so it can be interrupted and restarted
safely. Runners loop over seeds outermost, so a partial run still covers every dataset.
`03_run.py` takes `--lrs` / `--wds` to override the grid, and `--out` to write to a separate folder.
Keep ablations and checks out of `results/real`, because `05_analyze.py` treats that folder as the
main m = 3 benchmark.

## Protocol decisions (do not change silently; each has a reason in REPORT.md)

- **Selection is offline and matched.** Validation and test metrics are logged for every
  (checkpoint, config). Each test metric is read at the checkpoint chosen by its validation
  counterpart: set-MAE → set-MAE, NLL → NLL / held-out NLL, RPS → RPS. Never select on test data.
  Held-out raters are used only for evaluation.
- **Linear probes use Adam with a coupled L2 penalty, not AdamW.** Decoupled decay does not
  regularise 768–1,536-d linear heads; every method overfitted CommitmentBank.
- **Grid:** lr {3e-4 … 3e-2} × L2 {1e-3 … 10}; 2,000 steps; evaluated every 100 steps. Edge checks
  (`wd_check`, `mlp_lr_check`) showed it is not binding.
- **All methods share** data order, initialisation, splits (`03_run.split`, fixed seeds) and
  annotator sampling (`02_build.ANNOTATOR_SEED`).
- **Fine-tuning:** the head gets lr 1e-3 and its biases are initialised at the training-label
  marginal (`finetune.init_bias_to_prior`). Without this, CORAL's thresholds stay stuck. The backbone
  lr is chosen on seed 0 and reused for later seeds.
- **Statistics:** Nadeau–Bengio corrected t-test per problem (plain paired t-test for synthetic,
  where seeds are independent draws); Friedman/Nemenyi via `autorank`; Bayesian signed-rank via
  `baycomp`, which assumes higher is better, so its probabilities are flipped for our lower-is-better
  metrics (see `pairwise` in `05_analyze.py`).

## Conventions

- **Reuse open-source libraries** rather than re-implementing: `coral-pytorch` (CORAL/CORN),
  `autorank`, `baycomp`, `transformers`, `sentence-transformers`, `open_clip`. Hand-written code that
  duplicates a library must be checked against it in a test (see `test_losses.py`, `test_heads.py`).
- Match the surrounding code: module docstrings explain *why*, sparse inline comments, no new
  frameworks.
- New loss: add it to `losses.py` (`HEAD_OF`, `compute_loss`), add a test, and add a label in
  `05_analyze.py` (`LABEL`).
- New dataset: add a builder to `02_build.py` and an input loader to `finetune.load_inputs`. It must
  produce `X`, `K`, `item_id`, and per-m `mask_m{m}` / `ho_m{m}` / `valid_m{m}`.
- Report results honestly, including where soft-CORN loses; every claim in REPORT.md must trace
  to a table in `results/`.

## Environment gotchas

- PyTorch must be the CUDA build for GPU runs; install it first, then `pip install -r requirements.txt`.
- `run_cell` captures each training step in a CUDA graph, which cuts kernel-launch overhead when the
  CPU is busy. It falls back to eager mode on CPU. `test_cuda_graph_training_matches_eager` guards
  equivalence.
- A 6 GB GPU fits one fine-tuning process (CommitmentBank, 256 tokens, uses about 5.9 GB). Run
  fine-tuning jobs one at a time; frozen-feature runs can run two or three in parallel.
- When running under Claude Code, background shell jobs are killed after 2 hours. Split long runs by
  `--seeds` or `--datasets`; they resume where they stopped.
- On Windows, set `PYTHONIOENCODING=utf-8` when redirecting script output; the summary tables
  contain non-ASCII symbols.
